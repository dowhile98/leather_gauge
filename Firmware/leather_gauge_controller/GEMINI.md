# GEMINI.md - Leather Gauge Controller Project Context

## Project Overview

The **Leather Gauge Controller** is a professional firmware project for an industrial embedded system based on the **STM32F446RCTx** (ARM Cortex-M4F) microcontroller. Its primary purpose is the high-precision automatic measurement of the area of leather pieces moving on a conveyor belt.

### Key Technologies
- **MCU**: STM32F446RCTx (180 MHz, 256KB Flash, 128KB RAM).
- **RTOS**: **Azure ThreadX** (formerly Eclipse ThreadX).
- **Architecture**: Modular design with a custom **OSAL (OS Abstraction Layer)** that supports multiple RTOSes.
- **Peripherals/Communication**:
    - **Modbus RTU**: Communicates with 11 sensor modules (110 photocells total) via UART.
    - **Rotary Encoder**: Synchronizes measurement with conveyor movement using EXTI interrupts.
    - **DWIN Display**: HMI via UART (USART6).
    - **Printer**: Thermal ESC/POS printer for reports.
    - **EEPROM**: AT24Cxx via I2C for persistent configuration storage.
    - **RTC**: Real-time clock for timestamping.

## Project Structure

- `Core/`: STM32 HAL initialization and system setup (generated by STM32CubeMX).
- `leather_gauge_controller/`: Core application logic.
    - `app/`: Main task logic (`lgc_main_task.c`), HMI handling, and sensor processing.
    - `modules/`: Hardware abstraction modules for specific components (Encoder, Modbus, EEPROM, RTC, etc.).
    - `osal/`: OS Abstraction Layer providing a unified API for tasks, mutexes, semaphores, and events.
    - `config/`: Configuration files for the application and OSAL.
    - `middlewares/`: Integration of external libraries like nanoMODBUS, lwprintf, etc.
- `Middlewares/`: ST-provided middlewares (ThreadX, USBX).
- `Drivers/`: STM32 HAL and CMSIS drivers.
- `docs/`: System architecture documentation and variable lists.

## Building and Running

### Tools Required
- **STM32CubeIDE** (preferred) or GNU ARM Embedded Toolchain.
- **ST-LINK** debugger/programmer.

### Build Commands
- **STM32CubeIDE**: Import the project and use the Build (Ctrl+B) function.
- **CLI (Make)**:
  ```bash
  cd Debug
  make all -j$(nproc)
  ```

### Flashing
- **ST-LINK CLI**: `st-flash write Debug/leather_gauge_controller.bin 0x08000000`
- **STM32CubeIDE**: Use "Run" or "Debug" buttons.

## Development Conventions

### Coding Style
- **Naming**: Use `snake_case` for functions and variables. Use `PascalCase` for `typedef struct` types.
- **Prefixes**: Public functions should generally use the `lgc_` prefix (e.g., `lgc_main_task_entry`).
- **OSAL Usage**: **CRITICAL**. Do not call ThreadX APIs (`tx_...`) directly in application code. Use the OSAL wrappers:
    - `OsTask`, `OsMutex`, `OsSemaphore`, `OsEvent`.
    - `osCreateTask`, `osAcquireMutex`, `osReleaseSemaphore`, `osSetEventBits`, etc.
- **Thread Safety**: Always protect shared resources (like `measurements` or `data` structures) using mutexes defined in the OSAL.
- **Logging**: Use the `stm32_log` module for debugging. Configuration is in `stm32_log_config.h`.

### Architecture Patterns
- **Task-Based**: The system is split into multiple tasks (Main, HMI, Printer) with different priorities.
- **Event-Driven**: Tasks communicate primarily through event bits (e.g., `LGC_HMI_UPDATE_REQUIRED`).
- **Integration Algorithm**: Measurements are processed in "slices" triggered by encoder pulses. Each pulse represents a fixed displacement (default 5.5mm).
